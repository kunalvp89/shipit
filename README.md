# ShipIt v4.1.0

**ZIP → GitHub repository → Vercel project → production deployment → live URL**

ShipIt is a mobile-first deployment gateway for projects generated by coding agents. Upload a ZIP from your phone and ShipIt creates the GitHub repository, pushes the code, creates/links the Vercel project to that GitHub repository, starts a production deployment, waits for the result, and returns the live URL.

## v4.1 changes

- Removes the Vercel OAuth/App setup completely.
- Uses only two server-side environment variables: `GITHUB_TOKEN` and `VERCEL_TOKEN`.
- Creates the Vercel project through the Vercel REST API with the GitHub repository attached.
- Uses the GitHub branch as the Vercel deployment source.
- If Vercel has already started the first deployment, ShipIt detects and waits for it instead of creating a duplicate deployment.
- If no deployment is present, ShipIt starts one through Vercel's Git deployment API.
- Waits for `READY`, `ERROR`, or `CANCELED` (up to 3 minutes).
- Returns the production/live URL when available.
- Reuses an existing Vercel project only when it is already linked to the same GitHub repository.
- Normalizes the requested Vercel project name to a valid lowercase slug.
- Keeps the ZIP safety checks and wrapper-folder detection from v0.3.x.

Vercel's current project API supports creating a project with a Git repository, including a GitHub repository, and its deployment API supports Git-based deployments. See the official Vercel documentation linked below.

## Environment

```env
GITHUB_TOKEN=github_pat_...
VERCEL_TOKEN=vcp_...
```

Nothing else is required.

### GitHub token

The GitHub credential must be able to:

- read the authenticated user
- create private repositories
- create commits/trees/blobs and update branches

For a fine-grained token, grant repository creation and the repository permissions required for the Git data operations.

### Vercel token

The Vercel access token must belong to an account that can:

- create projects
- deploy to production
- access the GitHub repository being connected

If the Vercel account has not connected GitHub or does not have access to the repository, Vercel will return an API error; ShipIt surfaces that error instead of silently falling back to a manual import.

## Deployment flow

```text
Phone
  ↓
ShipIt
  ↓
Create GitHub repository
  ↓
Push files + commit
  ↓
Create Vercel project linked to GitHub repository
  ↓
Vercel production deployment from the branch
  ↓
Wait for READY
  ↓
🌐 Live URL
```

After the repository is linked to the Vercel project, future pushes to the configured production branch can be deployed by Vercel's Git integration.

## Important behavior

### Existing GitHub repository

ShipIt intentionally does not overwrite an existing repository. Use a new repository name for a new ShipIt deployment.

### Existing Vercel project

If the requested project name already exists and is linked to the same GitHub repository, ShipIt reuses it and deploys the selected branch. If it belongs to a different repository, ShipIt stops and asks for a different project name.

### ZIP structure

If an AI coding agent produces:

```text
project.zip
└── project-folder/
    ├── package.json
    ├── src/
    └── ...
```

ShipIt moves the wrapper contents to the repository root when `package.json` is found there.

The following are excluded from the upload:

- `.env*`
- `.git`
- `node_modules`
- `.vercel`
- `.next`
- `dist`
- `build`
- common OS/log files

Limits:

- ZIP: 25 MB
- individual file: 5 MB
- files: 500

## Vercel project naming

The UI accepts names such as `CreditBillReminder`. ShipIt normalizes them to a valid Vercel slug such as `creditbillreminder`.

## Run locally

```bash
npm install
cp .env.example .env
# edit .env and add GITHUB_TOKEN and VERCEL_TOKEN
npm start
```

Open:

```text
http://localhost:3000
```

## Security

Both tokens are used only on the server. They are never sent to the browser, stored in local storage, included in the GitHub repository, or written into the uploaded project.
